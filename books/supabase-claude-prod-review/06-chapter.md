メモの項目名を変えた後、アプリだけを昨日の版へ戻しました。昨日のコードは、今日のデータベースを読めるでしょうか。変更を小さな段階に分け、どこまで戻れるかを先に考えます。

**この章の到達点：** DB変更の各段階で、古いアプリが動く条件と、戻せなくなる地点を説明できる。

## 変更はアプリとデータベースの組み合わせで考える

対応メモに新しい項目を追加するとします。データベースへ列を足す作業と、アプリがその列を使う作業には順序があります。新しいアプリだけが先に公開され、存在しない列を参照すれば、利用者の操作が失敗する可能性があります。

逆に、アプリを古い版へ戻しても、データベースが古い構造へ戻るわけではありません。デプロイの切り戻しと、データの復元は分けて計画します。

## 追加、移行、整理を分ける

既存の`summary`を将来`title`へ変更するとき、列の追加、データの移行、読み取りの切り替え、旧列の削除を分けます。この章の後半で、各段階の切り戻し条件を表にします。

データ量や停止できる時間によって、適切な方法は変わります。大きなテーブルの一括更新、制約追加、インデックス作成には、ロックや処理時間への配慮も必要です。「同じSQLを検証環境で実行できた」だけで本番の所要時間まで保証しないようにします。

## 履歴として残す

Supabaseでは、スキーマの変更をmigrationとして管理できます。運用をmigrationへ統一したら、リモート環境での手動変更との食い違いを避けます。公式のmigrationガイドも、リモートへの直接変更が履歴の不整合を起こすことを説明しています。[公式資料](https://supabase.com/docs/guides/deployment/database-migrations)

教材SQLも、検証用に適切なmigrationファイルを作って管理します。CLIコマンドは導入済みバージョンのヘルプで確認します。破棄可能なローカルDBを初期化する操作を、本番の復旧手順に流用しないでください。

| 変更前に決めること | 記録する内容 |
| --- | --- |
| 適用する対象 | プロジェクト、環境、migration一覧 |
| 互換性 | 変更前のアプリが変更後のDBで動くか |
| 影響 | 読み書きするテーブル、権限、通知等 |
| 適用前の保護 | バックアップの対象と取得時点 |
| 中止条件 | 時間超過、ロック、エラー、想定外の件数 |
| 切り戻し | アプリを戻すか、追加修正か、復元か |
| 適用後の確認 | 主要操作、権限、データ整合性 |

削除した列の内容を、空の列を作り直すだけで復旧したことにはできません。復旧に必要なデータがどこにあるかまで書きます。

## 切り戻せる地点を表にする

ここでは、列名変更の計画を机上で点検します。実際にmigrationを実行した記録ではありません。

旧アプリは`summary`だけを使うものとします。新アプリは移行中、`summary`と`title`の両方へ同じ内容を書きます。このとき、二つの列を一つの更新で変更するなど、途中で片方だけが変わる状態を作らない方法が必要です。新しい列へのGRANTも別途設計します。

| 段階 | データとアプリの状態 | 旧アプリへ戻す条件 |
| --- | --- | --- |
| 追加 | `title`を追加。既存の`summary`を維持 | 旧アプリの読み書き・制約・権限が変わらない |
| 移行 | 読み取りはまだ`summary`。対応した書き手は両列を更新 | `summary`が最新であることを保つ |
| 切り替え | 全書き手の対応と両列の一致を確認して`title`を読む | 切り戻し期間中も`summary`への書き込みを続ける |
| 整理 | 切り戻し期間を終えて`summary`を削除 | 旧アプリはそのままでは動かない。別の復旧計画が必要 |

「全書き手」には、開いたままの古い画面、バッチ、管理ツールも含めます。旧アプリが`summary`だけを更新している間に、`title`を正として読み始めると古い内容が表示される可能性があります。旧経路を停止・更新し、移行中の書き込みを含めて両列の一致を確かめる方法を計画します。

この表は方式を選ぶための例です。本番へ適用するには、同時書き込み、データ量、NOT NULLなどの制約、ロック、権限、停止できる時間を合わせて検証します。「追加した列だから影響がない」とは決めません。

## 演習：空の列では戻らないものを考える

`summary`を削除した後に、旧アプリへ戻す必要が生じました。空の`summary`列を作り直せば、切り戻し完了としてよいでしょうか。

:::details 解答例と判断の理由
列の名前が戻っても、内容は戻りません。復元元、削除後に書かれた内容、制約・権限を確認し、どの時点のデータをどう再構築するかが必要です。旧アプリで読み書きと権限を確かめるまで、切り戻し完了にはしません。
:::
